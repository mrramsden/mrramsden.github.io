The A* algorithm, one row at a time

OCR A Level Computer Science. A* works like Dijkstra's algorithm but adds a heuristic: an estimate of how far each node is from the goal. Step through a worked example, then try two graphs yourself.

  1. Pick the unvisited node with the smallest distance travelled + heuristic.
  2. Check each of its unvisited neighbours. Is the distance travelled through this node shorter?
  3. Stop as soon as the node you pick is the goal, then read the route backwards.

You can also use the left and right arrow keys.

Know what a heuristic is

A heuristic is a rule of thumb: an estimate of the distance from each node to the goal. It steers the search towards the goal so that fewer nodes need to be checked. In the exam it is usually the bold number next to each node.

Three numbers per node

Each row needs the distance travelled, the heuristic, and the two added together. Write the working, such as 3+2=5, so the marker can follow it.

Choose by the total

Visit the unvisited node with the smallest distance travelled + heuristic. Choosing by distance travelled alone is Dijkstra's rule, and choosing by heuristic alone ignores how far you have already come.

Update the distance travelled

When you check a neighbour, work out the new distance travelled through the current node. If it is shorter, cross out the old values, write the new distance, add the heuristic again, and change the previous node.

Stop at the goal

Once the goal node is the one with the smallest total, visit it and stop. Examiners have seen candidates carry on through every node as if it were Dijkstra's algorithm. Nodes you never visit simply stay unticked.

Cross out, don't rub out

Put a line through ∞ or any old value when you replace it, and write the new value beside it. Markers want to see the table change as the algorithm runs.

Finish the answer

Give the route in order from start to goal and the total distance. The distance is the distance travelled to the goal, which equals its total because the goal's heuristic is 0.

Comparing with Dijkstra

For a similarity, both are pathfinding algorithms that find the shortest route. For a difference, A* uses a heuristic, so it usually reaches the goal faster and visits fewer nodes, while Dijkstra's algorithm finds the shortest distance to every node.
