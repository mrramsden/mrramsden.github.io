Dijkstra's shortest path, one row at a time

OCR A Level Computer Science. Step through a worked example using the table method, then try two graphs yourself.

  1. Pick the unvisited node with the smallest distance anywhere in the table.
  2. Check each of its unvisited neighbours. Is the route through this node shorter?
  3. Repeat until every node has been visited, then read the route backwards.

You can also use the left and right arrow keys.

Set the table up first

The start node gets a distance of 0 and every other node starts at ∞. Examiners regularly see answers that forget to give the start node 0.

Pick from the whole table

The next node is the unvisited one with the smallest distance anywhere in the table, not just the closest neighbour of the node you have just visited. Following neighbours is the most common way to get the wrong route.

Cross out, don't rub out

When you find a shorter route, put a line through the old distance and write the new one beside it. Markers want to see that a value was overwritten, and it is often worth a mark on its own.

Keep going

Dijkstra's algorithm does not stop when you first reach the goal. Carry on until every node has been visited, because a shorter route can still turn up.

Show the working

Spotting the route by eye only earns a couple of marks. The table is the evidence that you used the algorithm.

Finish the answer

State the route in order from start to goal and the total distance. Get the route by starting at the goal and following the previous node column backwards.
